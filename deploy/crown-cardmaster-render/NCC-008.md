# NCC-008 — Counterparty NOMNI order-book evidence

This development gate adds **read-only, source-backed open-order evidence**, not a market price. The Counterparty Core v2 API returned an empty NOMNI/XCP and NOMNI/BTC order book when checked during the gate; subsequent requests may differ. An empty successful response is distinguished from API failures and must never be promoted to liquidity, an executed trade or valuation.

## Live sources inspected

- `https://api.counterparty.io:4000/v2/`
- `https://api.counterparty.io:4000/v2/orders/NOMNI/XCP?status=open&limit=10`
- `https://api.counterparty.io:4000/v2/orders/NOMNI/BTC?status=open&limit=10`
- `https://api.counterparty.io:4000/v2/blocks/972716`

The API provides `block_index`, `tx_hash`, raw give/get assets and quantities. Block lookup provides `block_hash` and `block_time` (Unix seconds). The latter is an **order inclusion block timestamp**, NOT the time of a trade and NOT evidence that an old open listing is currently executable.

## New implementation

- `server/crown-metadata/counterparty-order-evidence.mjs` uses a fixed HTTPS Counterparty Core endpoint, two allowlisted NOMNI markets, bounded response body (64KiB), request timeout, strict order ID/status/pair validation, and at most five block confirmations per pair.
- `GET /api/crown/order-evidence` returns `neo.crown.counterparty.order-evidence.v1`, per-pair `no_open_orders`, `open_listings_present`, or `unavailable`, observed counts, sampled transaction hashes, optional block timestamps, and `price:null`.
- The Crown gallery adds **Verify NOMNI order books**, a user-triggered display of source status. It never inserts a guessed price.
- No secrets, signing, wallets, purchases, issuance, background polling, broad provider configuration, paid services or production promotion.
