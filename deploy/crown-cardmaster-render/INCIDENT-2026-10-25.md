# NEO Crown staging availability incident — 2026-10-25

## Incident scope and evidence

- **Crown CARDMASTER Free web runtime**: initial public `/healthz`, `/studio/`, and read-only market-evidence requests returned HTTP 503 and Render's "Application loading" page. Subsequent retries returned HTTP 200 with the expected health JSON, gallery, Studio and read-only `/api/crown/order-evidence`. No new Crown deployment or environment configuration was required.
- **Crown static fallback**: `https://neo-crown-cardmaster-staging.onrender.com/` remained HTTP 200 and usable for offline example cards. This static site must **never** imply that illustrative prices/claims are verified.
- **Crown GEM**: first request returned the Render 503 loading page, later `GET /health` and root returned HTTP 401. The running GEM service enforces authentication; **401 is not proof of authenticated application health**. Do not bypass or publish credentials.
- **Shared NEO Edge**: initially HTTP 503 Render loading page, then root returned HTTP 200. This is consistent with the documented Render Free idle behavior.
- **Main `neo-system` service**: continued returning HTTP 502. Render service configuration contains start command `Yarn start`. Actual runtime logs state `bash: line 1: Yarn: command not found` and `Exited with status 127`. The main GitHub root `package.json` has no `start` script, but does have `build` (Vite static build) and `preview`. **Do not attempt further blind redeploys before fixing the Render startup command.**

## Cause and impact assessment

Render documents that Free web services sleep after 15 minutes without traffic, and wake when a new request arrives; spin-up takes around a minute and can present temporary 503 loading screens. This is the **probable** cause of the transient Crown/Edge responses. Crown Render service is not suspended and last Crown deploy was successful. A persistent Free plan usage restriction was **not** observed.

The main NEO service has a **separate confirmed configuration bug** unrelated to the Crown media library. It is configured to auto-deploy `main`, so incidental commits repeatedly trigger builds that then fail at startup. It also has outstanding npm audit findings. Do not introduce financial or wallet operations while service identity and hardening are unresolved.

## Recovery action

- Retained the last verified Crown runtime release `e38b17393e5e5e2b286039963fd27324209c90bf`. No restart, paid plan changes, database/secret modifications or signing operations.
- Confirmed Crown /healthz and /studio HTTP 200; market metadata remains a read-only set of 3 example cards with `quote:null`, unverified issuer, reserves and financial values.
- Retained existing static fallback.
- Hardened the GitHub staging HTTP smoke helper to retry only **GET** 502/503/504 responses and connection failures (up to 5 attempts, 16s backoff), eliminating false incident pages during normal Free spin-up while still failing persistent outages. POST/write-denial checks are never retried.
- No scheduled keepalive: this preserves Free-tier limits and avoids unnecessary usage.
