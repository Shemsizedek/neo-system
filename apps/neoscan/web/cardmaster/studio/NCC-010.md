# NCC-010 — Crown Media Library & AI Artwork Intake

**Scope:** deployed/staged only after CI. Reuse the existing Render Free Crown CARDMASTER site and GitHub source branch. No external AI generation, paid credits, wallet or production publishing.

## Architecture and operator workflow

1. Produce original/authorized artwork in ChatGPT, Canva, ElevenLabs or an approved source **outside this site**. Their platform availability, generation entitlements, model output rights and costs have not been verified by this build; no direct image API is called.
2. Open `/studio/` and use **06 / Crown Media Library** to import an exported PNG, JPEG or WebP. The browser validates image signatures, decodes the image, resamples to a maximum 1600-pixel side and normalizes as PNG (embedded source EXIF is not copied).
3. Declare the creative source and artist/source account. Choose **created**, **licensed** or **commissioned** rights and explicitly attest to permission for private Crown designs. Self-attestation is not independent rights verification.
4. The normalized image is SHA-256 hashed and stored as a Blob in **that browser's IndexedDB**, or nonpersistent memory fallback if blocked. No image is uploaded to the Render server or a third party. Limits: 6 MiB input; 4 MiB normalized PNG; 12 images/24 MiB total.
5. Select **Use on card** → **Generate artwork**. An inline sanitized PNG is embedded in the **front** SVG composition, while the back remains procedural vector art. The images can be previewed and exported as mixed-media SVG or 1440×2080 PNG. The SVG contains the image bytes and should be treated as private artwork until rights review.
6. Export the off-chain JSON provenance record alongside both faces. Manifest records media SHA-256, user-declared provider and rights, unknown independent verification, version, and previous revision hash. The local vault retains a reference to image content; losing the browser vault may prevent revision restoration.

## Security contract

- **No direct AI API:** ChatGPT, Canva and ElevenLabs are manual-source choices, not active authenticated integrations. No server credentials or API tokens are handled in the browser. ElevenLabs generation could consume credits; not requested or performed.
- Accepted raster byte signatures only; SVG/HTML/remote URLs rejected as imports. Original image bits are not stored; Canvas-normalized PNG is retained. Canvas encoding may retain generic encoder metadata but not the original EXIF.
- User-provided fields are written as plain DOM text or XML-escaped by the existing studio renderer. The only embedded image source accepted in the SVG is a valid `data:image/png;base64,` generated locally from the verified normalized Blob.
- No media upload/write route. New media JS module paths are specifically allowlisted and otherwise inaccessible. CSP limits scripts to same-origin and images to self, blob and data (for locally generated artwork).
- Media deletion requires an explicit in-browser confirmation and warns of breaking older revisions.
- `ai_generated` is null for a user-declared external AI source, **not automatically true**; creator/rights identity is not verified. Publication, issuer, market and backing approval remain false.
- Download files only after manual quality/rights review. A media digest is an **unsigned off-chain integrity checksum**, not a certificate of copyright, token ownership or chain issuance.

## Free-platform deployment

This builds **inside the existing Render Free service**; no database, storage bucket, always-on worker or paid provider is created. The media vault is per-browser, non-synchronized and not suitable as a durable or multi-user asset management backend. A centralized rights-reviewed media library on a verified free storage connector can be added separately with authentication, retention limits, backups and authorization.
