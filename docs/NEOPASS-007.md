# NEOPASS-007 — Live CounterPay access verification

Observed October 24, 2026 in the user-authorized Chrome session at https://counterpay.holytemples.org/.

## Confirmed live

- CounterPay /owner rendered: "Your ChatGPT identity is verified."
- After the user completed wallet selection/unlock, the wallet rendered "Unlocked on this device" and Settings rendered "Signer unlocked on this device."
- A legacy mainnet address is selected. Its value is intentionally omitted from this public development record.
- https://counterpay.holytemples.org/integrations.html states public account sign-in is not connected yet, while ChatGPT owner access supports balance reads, confirmation checks and checkout review links.

## Scope of evidence

Owner login and local wallet unlock are observed UI states. Neither constitutes a successful NEOpass challenge signature, issuer/session interoperability test, deployed wallet-link API, passkey enrollment test or blockchain transaction. No signature was requested or generated by the agent, and no asset transfer or token update was performed.

## Integration gap

The CounterPay connector exposes balance, transaction status and checkout review operations, not ownership-message signing. The inspected settings/integrations surfaces did not expose a NEOpass ownership-message signing flow. A repository search under Shemsizedek returned no CounterPay repository/code matches; this does not establish that the source does not exist elsewhere.

## Next implementation gate

Locate the deployed CounterPay source and add an explicitly reviewed wallet-link ceremony: request the exact server-generated challenge, show origin/address/network/purpose/expiry, obtain user approval, sign locally without exposing keys, submit the signature to the authenticated NEOpass API, and confirm the persistent link. Bind the live owner identity through a server-side issuer adapter; do not export browser cookies or use an unlocked wallet as account authentication. Keep checkout approvals and ownership proofs separate.
