# NEO-BMI-007 — Authenticated Gateway and Persisted History
Adds a separate fail-closed secure gateway and transactional PostgreSQL event chain. The earlier BMI-005 gateway remains a legacy prototype and MUST NOT be deployed or routed publicly. The secure gateway requires an explicit `authorize(req)` callback, authenticated access even for health, an allowed asset list, and a history store. No unauthenticated access.
`createPostgresHistoryStore(pool)` serializes per-asset writes via PostgreSQL transaction advisory locks. The schema from BMI-006 must be migrated manually, with dedicated database privileges and an external immutable copy for tamper evidence. An append-only application role alone does not prevent database administrator alteration. 
The secure gateway returns the database append result's event hash only after successful persistence. A history-store adapter that does not return a persisted event hash fails closed. Claim verification is provider correlation, not proof of legal title, perfected security, Bitcoin consensus, or reserves.
Tests: `node --test server/neo-bmi/secure-gateway.test.mjs`. Existing legacy gateway stays unconnected and must be removed or disabled in deployment configurations.
NEOpass OIDC/JWKS verifier has NOT been implemented: inject a verified authorization provider before integration. Database not provisioned, live node data not connected, no deployment.
