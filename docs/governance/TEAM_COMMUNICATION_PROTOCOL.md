## Hand-off rules
1. Keep one authoritative decision record in the version-controlled register; link it from ChatGPT.
2. Each workstream names a human accountable owner. AI drafts and assists but cannot hold Temple office or authorize consequential actions.
3. Daily async check-ins; weekly review by authorized leadership (proposed cadence, not scheduled).
4. For urgent incidents, use an approved human escalation route outside ChatGPT. Do not assume chats are monitored.
5. Share only minimum necessary information; verify project membership and connector permissions before inviting collaborators or exposing documents.
6. Tag requests as PROPOSED, APPROVAL NEEDED, APPROVED, IMPLEMENTED, VERIFIED, or BLOCKED; retain approval evidence.
7. For external messages, legal/financial commitments, production changes or canonical Temple policy, obtain the required authorized human signoff first.

## ChatGPT workspace navigation checklist
- Confirm whether the team uses one shared Project 144 project and who has access.
- Set project instructions that reference Temple authority, source precedence, evidence status, and escalation.
- Create separate topic chats inside the project, not separate uncontrolled sources of truth.
- Store final artifacts in approved GitHub/Drive/records systems and link them in chats.
- Audit sensitive files and connected app permissions before sharing.

## Acceptance
Named steward, approved member access list, canonical decision register, tested communications cadence and escalation contact, human approval to publish the protocol.
