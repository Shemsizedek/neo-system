# NEO Miner v0.20 — CES Coordinator Gateway + NEO Wire Settlement Bridge

## Purpose

Connect Community Exchange System (CES) mutual-credit activity and NEO Wire settlement routing to NEO Miner commerce without collapsing distinct ledgers into one representation.

## Settlement principle

A customer order is not paid merely because an account balance exists. The commerce system must reconcile an actual posted/settled transaction event against the order.

## CES flow

CES coordinator account → account/trade sync → normalized CES trade → exact order reconciliation → payment event → contract activation gate.

Required CES live configuration:

- HTTPS coordinator endpoint
- CES exchange ID
- coordinator account ID
- secret reference held outside client-visible records
- merchant/credit account mapping
- customer/debit account mapping where applicable
- exchange-specific unit/currency and limits

CES remains a mutual-credit ledger. It is not represented as BTC, fiat, or a blockchain transaction unless a separate conversion/settlement actually occurs.

## NEO Wire flow

NEO Miner order → payment rail → NEO Wire route → settlement instruction → external/underlying rail event → reconciliation → order payment confirmation.

Supported NEO Wire route identifiers:

- NEO_WIRE_BANK
- NEO_WIRE_BTC
- NEO_WIRE_LIGHTNING
- NEO_WIRE_XCP
- NEO_WIRE_CES

NEO Wire acts as an orchestration and communications boundary. The software must not claim custody, signing, broadcast, banking, carrier, or CES coordinator authority unless those production services are separately configured and authorized.

## Fail-closed rules

- CES coordinator disabled or missing HTTPS/IDs/secrets → no live CES payment confirmation.
- CES trade status not POSTED/SETTLED → no reconciliation.
- Wrong exchange, debit account, credit account, unit, or amount → payment mismatch.
- NEO Wire DEMO instruction → cannot reconcile as live settlement.
- Missing or mismatched settlement event → order remains unpaid.
- Payment confirmation alone does not prove BTC production or mining performance.

## Persistence

Use:

- `commerce/neo-miner/ces-coordinator.schema.json`
- `commerce/neo-miner/ces-transaction.schema.json`
- `commerce/neo-miner/neo-wire-settlement.schema.json`
- `commerce/neo-miner/payment-event.schema.json`
- `commerce/neo-miner/order.schema.json`

## Future live connectors

The current gateway is provider-neutral. Real CES synchronization must be implemented against an authorized CES API or coordinator integration. NEO Wire bank/BTC/Lightning/XCP/CES routes likewise require their respective live provider/network connectors and production credentials before LIVE mode is enabled.
