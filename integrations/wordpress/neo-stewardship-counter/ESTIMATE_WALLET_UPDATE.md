# NEO Counter 0.21.0

Update estimate now intercepts its form submission and fetches the pricing endpoint in place. Quantity and bond remain selected. The returned quote uses the selected ledger/currency, synchronizes hidden checkout fields, changes URL parameters through replaceState without navigating, disables the button during the request, and provides a retry message on failure. A request sequence prevents a late response replacing a newer selection. Changing pricing context disconnects the old wallet session. The GET form remains a no-JavaScript fallback; the updated behavior requires the module to load.

NeoMask remains the single member entry point. Its chooser lists Horizon Wallet, XCP Wallet, Freewallet.io, Counterpay and NEO Pay, plus an installed NeoMask vault. It uses real provider detection rather than branding an address entry as a wallet connection. Unavailable entries are labelled accordingly; official wallet links are distinct from connection actions.

Horizon adapter is based on the primary upstream source at https://github.com/UnspendableLabs/Horizon-Wallet : web/horizon-provider.js, web/content-script.js and lib/setup.dart. It uses request(method, params), handles the result.addresses / result.hex envelope, requires a mainnet Legacy address for the current checkout, and remains CP2-only. Horizon PSBT signing requires explicit reviewed input indices for the selected address and SIGHASH_ALL; connection never signs or broadcasts. The published older provider reopens getAddresses when rechecking accounts; the adapter does not silently substitute a stale cached address.

XCP Wallet retains its documented request({method,params}) adapter. NEO Pay's existing explicitly declared full bridge contract remains supported. Freewallet, Counterpay and NEO Pay may register an owned bridge under window.neoMaskWalletAdapters[id], with neoMaskAdapterVersion=1, ledgers, connect, getAccount, signPsbt and disconnect. Every session must return its explicit ledger, mainnet and Legacy address; router continuity and change checks still apply. This is an integration contract, not evidence a third-party app has installed a bridge. No documented universal browser connector was established for Freewallet.io, and no complete deployed Counterpay/NEO Pay bridge was proven during this gate. Those choices are not falsely reported as connected. External wallets remain necessary on the user's device; a web page cannot install them or extract their credentials.

Tests cover prevented form navigation, exact updated quantity/price, context synchronization, retry state, documented Horizon call shape/envelopes, explicit signing inputs, unsupported network/ledger rejection, no signing during connect, all five chooser entries and versioned bridge registration. Existing quote, router, wallet, privacy and PHP syntax tests pass. No live member-wallet approval, key, signature or financial transaction is used by these tests.
